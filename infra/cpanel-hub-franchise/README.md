# Deploy the RedCat Hub Franchise application

The Next.js site uses a static export. cPanel receives applications over HTTPS and writes them to MySQL. The existing application table can hold the new terms version in its JSON data. The careers endpoint and its configuration are separate.

1. Import `schema.sql` if the application table does not exist. Use a database account with INSERT and SELECT on that table. The dashboard uses the same connection by default. An optional `review_database` block can supply a dedicated account with SELECT only. Enable PHP 8.2 or later with PDO MySQL and mbstring.
2. Create `redcat-hub-franchise-config.php` from `config.example.php` in the parent directory of the handler's document root. Keep it outside every web root with owner-only access. Create the configured rate limit directory outside every web root with mode 0700 and PHP ownership. The limiter permits 10 POST requests per client address per minute and 120 overall on one host. With a reverse proxy, configure the web server to resolve the real client address from a trusted proxy. With several backend hosts, apply a shared limit at the gateway.
3. Choose a staff sign-in method. For one sign-in, upload the current `infra/cpanel-careers/admin.php` as `admin.php` and the current franchise dashboard as `hub-admin.php` on the same HTTPS host. Add the exact authorized Careers admin username to `careers_reviewers` in the franchise config. Sign out and sign back in to Careers to see the Hub Franchise link. Only an allowlisted Careers account with a fresh sign-in can open it. Hub review only runs SELECT queries. The existing Careers config and both application tables are used as before. The shared sign-in needs PHP write access to the private rate-limit directory. If the directory is unavailable, staff can still sign into Careers and see a notice with the next step. Shared staff sessions expire eight hours after sign-in. If you already use an HTTPS staff gateway with MFA, keep the verified `REMOTE_USER` names in `reviewers`. Both lists default to empty.
4. Upload `hub-apply.php`, `hub-admin.php`, `application-schema.json` and `hub-catalog.json` together to the handler's document root. Coordinate this update with the frontend release because they share the receipt contract and terms version. The default endpoint is `https://apply.bestproducts.lk/hub-apply.php`. Override it at frontend build time with `NEXT_PUBLIC_HUB_FRANCHISE_CPANEL_URL` if needed. Deploy the existing careers files and their config independently.
5. Use staging origins and accounts to verify one successful synthetic submission, a retry returning the same reference, and a failed database write showing no receipt. Check an approved reviewer can open the matching record and export CSV, then verify a request without an approved identity cannot access the dashboard.
6. Approve the English and Sinhala notice and terms before enabling intake. Assign an owner for access and deletion requests, set the firm's retention schedule for records, backups and exports, and enforce it with the database and file owners. Retain the terms text for each published version. Audit export events in the protected PHP logs and remove reviewers when access ends.

The hub catalog is shared by the map, form and server validation. Update the catalog in this directory once and deploy the frontend and PHP files together.

## Add the Point Franchise application

1. In cPanel phpMyAdmin, select the database in the top-level franchise `dsn` and import `point-schema.sql`. It creates `point_franchise_applications` and `point_franchise_files`. The top-level MySQL account needs SELECT, INSERT and UPDATE on those tables for registration and staff review. The optional `review_database` setting remains the regional Hub review connection.
2. Upload `hub-apply.php`, `hub-admin.php`, `point-apply.php`, `point-review.php` and `point-application-schema.json` to the existing `apply.bestproducts.lk` directory alongside the Hub files. Upload the updated Careers `admin.php` for a direct link to Point Franchise. Sign in with the existing allowlisted Careers admin account and open `hub-admin.php?type=point`. For staff uploads, enable PHP fileinfo and set `upload_max_filesize` to at least 5 MB and `post_max_size` to at least 22 MB. Protect the application database and its backups with the same access and retention rules as other sensitive verification records.
3. Deploy the Next.js static export with the updated Dealers page, the Point application and its privacy notice. The Point intake endpoint defaults to `https://apply.bestproducts.lk/point-apply.php`. To test another endpoint set `NEXT_PUBLIC_POINT_FRANCHISE_CPANEL_URL` at frontend build time. The browser's website origin must be in the private franchise config's `allowed_origins` list.
4. Approve the Point privacy notice and terms before opening registrations. Applicants enter a preferred town or area. Staff confirm location availability and can record manual mobile confirmation in the interview. SMS verification and an availability catalog require service credentials and approved Point data. Staff can record the selection stage, enter scores and store premises photos and verification PDFs behind the existing sign-in. Point CSV exports omit documents and photos.
5. In staging, submit a synthetic Point registration, open it from the Point Franchise tab, save a qualification and verify the CSV. Test a regional Hub submission through its existing form as well.

The public Point form issues a receipt only after the cPanel API confirms a database save. Qualification happens in the staff dashboard.

If you previously imported the SQL from the removed `infra/cpanel-point-franchise` directory, check the existing Point table before importing this one. The earlier schema used `rc_ref` and `stage_mode`. Preserve and migrate those records before switching to the shared backend.
